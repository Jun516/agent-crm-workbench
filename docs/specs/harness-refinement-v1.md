# 工作台只读候选自精炼 v1

状态：实现接线；本地离线验证与真实服务联调分别记录。此功能不修改模型权重，不宣称复现 Harness² 论文的完整系统或业务准确率提升。

## 范围与入口

目的地为**核心**：它处理现有工作台的执行、权限和预算；不开启时普通工作台保持原路径。入口是 `/app/ai/workbench` → 任务设置 →“多候选自精炼（只读）”。`POST /api/v1/ai/workbench/runs` 可显式传 `refinement: { maxRounds: 2, candidateCount: 2 }`。轮数限制 1–2、每轮候选 2–3，界面固定最多 2×2。仅独立 inspect 任务可用，act 和 Mission 在写入前被拒绝。

## 执行过程

1. 原 API 继续验证经理身份、组织、对象范围、Agent 版本及模型凭据，选项进入 root Run 的 `runtime_state`。
2. `workbench-start-job.ts` 选择自精炼路径，避免再启动原机会复盘协作造成双重开销。
3. `refinement-workbench.ts` 复用 `runWorkbenchCollaboration`。每个候选为现有持久 specialist 子 Run，键为轮次和候选序号；其工具只能取当前 Agent 已授权且 effect 为 read 的交集。
4. 候选顺序运行，避免并行请求一起通过陈旧预算检查。自精炼最多使用原预算的 65%，为父 Run 保留至少 35% 和两回合；每候选最多两回合、六次工具调用，总体 120 秒，候选另有 45 秒限制。实际用量包含淘汰分支，未知成本停止继续调用。检查发生在回合边界，已在途的一次模型请求可能超出目标额度，不能称供应商硬限额。
5. `refinement.ts` 的 Probe 检查完整状态、成功观察、缺失材料、内部草稿、截断和结构化字段自相矛盾。只有通过者可参与覆盖评分选择；分数是可观察覆盖的排序依据，不是正确率。不同分支事实/版本冲突保留并使结果待复核，不按票数裁决。
6. 下一轮以已经选中的上一轮候选为待核查草稿继续改进。草稿放在用户材料的 historical_data 块，不拼入系统政策，且每候选仍需自己的只读工具观察。淘汰分支仅提炼代码白名单中的方法码，例如“补查缺失材料”“重新核对来源版本”。下一轮和父 Run 读取这些方法提示；不会回写组织政策、客户档案、Mem0 或模型权重。
7. 每轮 Probe、赢家、淘汰 ID 与方法码持久化在 root `runtime_state`，摘要通过现有 `policy_checked` 事件（gate=`refinement_probe`）进入工作台时间线。完整候选报告和工具观察仍在其子 Run 中。
8. 父 Run 接收选中候选和所有冲突，按剩余预算完成汇总。没有有效候选或保留证据冲突时不把运行直接当作正常完成。原独立事实评测与语义 Judge 入口保持不变，后续语义高分不能覆盖 Probe 的明确拒绝。

## 经验库的权威与隐私

“经验库”是现有 root Run 状态中白名单方法码的受限视图，不是新增一张任意文本知识表。复用查询同时限制组织、Agent、root 类型及已结束状态；解析时还核对 Agent 版本、算法 revision、创建时间（七天有效）和枚举集合。最多读取最近二十次、采用八条经验记录。拒绝模型自由文本、客户姓名/偏好、任意附加字段、未知方法码和未来时间。

提示中明确“低权威方法提示”；当前业务事实、已发布组织政策和工具授权始终优先。不自动发布规则、修改知识库或执行对客动作。用户要删除客户数据时，这些方法码不含客户事实；候选原始资料仍遵循现有运行数据生命周期。

## 恢复、取消及限制

- 复用原子 Run 的存在性、领取租约和已保存结果；重试时同轮/同序号键可复用已完成候选，避免重复正常完成的分支。它不是跨系统 exactly-once 承诺。
- 每次候选之间和持久化之前复查 root job 执行权，并共享根取消信号。取消不能撤销已经消耗的模型请求。
- Probe 是确定性结构和观察检查，不能穷尽自然语言事实错误，也不证明客户已接受、报价已获批或消息已发送。
- 每候选两回合可能只得到有限证据；预算或超时可提前结束。无需为达成“两个完整轮次”无限增加调用。
- 真实模型、Supabase、浏览器全链路及生产服务验收尚须独立证明；离线替身测试不会表述成真实业务效果。

## Living System Checklist

1. 输入：工作台受授权的创建运行 API 与固定 Agent 版本。
2. 输出：`workbench-start-job.ts` 的父 Run 汇总输入、剩余预算和待复核状态。
3. 记录：持久 specialist Run、root runtime_state 和 policy_checked 事件。
4. 界面：`AgentCrmWorkbench` 的原有子任务列表及事件时间线，Probe 事件专用标签。
5. 门口：现有 `/app/ai/workbench` 任务设置，不增加隐藏页面。
6. 防停滞：共享预算、取消、超时和原持久任务失败处理；失败状态明确，不自动无限重试。
7. 配置：任务设置复选框；默认关闭；动作模式禁用并显示原因。
8. 人机连续：运行报告保留冲突和缺失材料供人复核，后续新任务可明确补充方向；不升级为自动发送。
9. 反馈：淘汰 Probe 产生枚举方法提示，下轮及同版本后续运行复用；没有自动修改生产规则。
10. 地图：`docs/architecture/harness-refinement.architecture.json` 记录入口、候选、Probe、经验和父执行之间的真实连接。
