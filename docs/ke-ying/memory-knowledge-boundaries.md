# 客赢智销：客户记忆、画像授权与知识依据

依据：本地附件源码，2026-10-27。下述“已有”来自静态源码；本次新增须以测试记录判断，不代表生产验收、模型效果或实际客户数据。

## 已有基础

- SQL 保存联系人档案、笔记、服务边界检查点与确认事实；Mem0 只为本地拥有的记忆标识提供可选排序，返回正文仍从 SQL 读取。
- 客户事实、当前服务摘要、组织政策与产品知识分别有不同权威级别，旧摘要不能升级成当前业务事实或公司批准。
- WeKnora 只读检索同时限定安装绑定的 KB 白名单和 Agent 已授权来源，实际读取已发布页面并检查来源文档，保存页面内容 hash 与来源版本清单。
- 回看观察会重新核对 Agent 的当前知识授权，Wiki 回执还需远端资料仍然有效。
- 隐私撤销、匿名化与合并已有清理和读取资格机制。远端写入超时需保留未知状态和清理回执，不能凭空列表声称供应商备份已全部擦除。

## 本次新增与修复

### 1. 为画像提供独立授权投影

入口是现有 `crm_get_contact`，没有新增任意推断或自动收集字段。`profile_context` 只投影 SQL 中已有的出生日期与标签，携带当前 `updated_at` 和授权时间。要求联系人未匿名化、未合并、未屏蔽，且 `consent.profiling.granted_at` 为有效的非未来时间；显式撤回或否定状态不放行。营销同意不代替画像同意。

未获画像授权时，返回明确的 `not_permitted`，不返回画像正文。姓名和业务联系方式等原有基础档案读取仍走原权限；这不允许调用方把基础档案或历史聊天重新拼成未经同意的画像。

### 2. 避免外部等待后返回过期身份

工具先核对联系人，再读取可选记忆，等待结束后重新读取 SQL 档案与同意状态。若其间被匿名化或合并，先前已读的身份、出生资料和确认记忆全部从本次输出丢弃。Mem0 事实函数也在最终 SQL 重读后增加联系人资格复查，防止“复查通过后、SQL 尚未返回时发生匿名化”的窗口泄漏旧正文。

它是读取边界的保守复验，不声称能撤回已经交给模型、浏览器或外部系统的数据。

### 3. 页面撤回发生在文档核对期间，也要生效

原流程复查来源文档与 CRM 来源记录，但页面可能在这段等待中被撤回或改版。本次在检索和回看中增加最后一次页面读取；正文、发布状态、版本或来源清单不再一致就不暴露该证据。交付前还核对来源与组织启用状态，停用中的检索不再写入可用回执。

### 4. 回执正文必须与记录的 hash 一致

回看先校验本地回执正文与 manifest 的 `content_hash`。否则，即使远端页面有效，也不能为被修改的本地正文背书。有效远端来源与有效本地回执需要同时成立。

## 处理流程

```text
crm_get_contact
  → 原档案权限与组织校验
  → SQL 确认事实 / 可选 Mem0 排序
  → 重读当前档案、匿名化/合并/同意状态
  → 不合格：只返回不可用状态
  → 合格：基础字段 + 有同意才有 profile_context

Agent 授权来源 + 安装 KB 白名单
  → 搜索线索
  → 读实际发布页面
  → 读并复核来源文档
  → 再读页面 + 来源 + 组织启用
  → 一致才保存与返回证据
```

## Living System Checklist

1. 输入：`getContactHandler` 的组织范围档案、SQL 确认事实及现有知识授权/服务绑定。
2. 输出：现有 `crm_get_contact`、`searchCompanyWiki`、`readCompanyWikiEvidence`，供 Agent 工具和工作台证据回看使用。
3. 记录：沿用 MCP 工具调用审计、Run 工具观察和 Wiki manifest；无新数据库写入渠道。
4. 界面：沿用工作台的运行结果/观察和现有证据详情入口；没有新增页面。
5. 入口：现有联系人工具和工作台知识工具，不需要新导航。
6. 防停滞：读取失败返回 unavailable/拒绝证据，原业务可继续走人工核实；不为不可靠资料制造成功状态。
7. 配置：沿用 contacts consent 的按目的记录、知识源与组织集成启用；没有新环境变量。
8. 双向衔接：人维护确认档案与授权，Agent 读取可追溯字段；不满足时由原工作台返回缺口，不能自动重新授予。
9. 反馈：撤回/改版/匿名化使下一次读取收窄；竞争与篡改反例固定为回归测试，不能靠模型自行承诺。
10. 地图：`docs/architecture/agent-services.architecture.json` 增加 SQL→画像授权投影→Pi 的真实数据流。

改动归属：核心得到只读授权与复验，不改变组织未启用可选服务时的普通 CRM 能力。没有新增 Schema；不要求远端 Mem0、WeKnora 或 Langfuse 必须在线。
