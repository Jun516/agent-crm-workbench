# 客赢智销：MCP 任务工具清单与最小授权

## 原有能力与本次变化

原有底座已经具备按请求装配的 Streamable HTTP MCP、Zod 参数结构、组织/角色/读写范围检查、审计和短期运行令牌。不能将这些机制计为本次从零开发。

本次补充：临时令牌的 `scopes` 增加精确工具清单。以前短期令牌虽由某次任务签发，但数据库只记录 MCP 读写类别；现在同时保存该任务获准的工具名称，HTTP 和进程内调用都受限制。

## 处理流程

1. 发布的 Agent 工具选择经过 Harness 禁用项过滤，形成当前任务清单。
2. `buildEphemeralTokenScopes` 生成读写类别、运行身份及精确名称授权，持久令牌与进程内身份使用同一函数。
3. `mcp:tools:restricted` 表示存在显式清单，`mcp:tool:<name>` 表示单项授权；空清单表示零工具。
4. MCP 发现阶段只注册角色、读写范围和工具清单均允许的工具；进程内桥也不装配清单外工具。
5. 执行前再次核对三种条件，实际业务 Handler 继续检查组织和资源范围；成功/拒绝走既有审计。
6. 原有任务结束撤销和短期过期机制继续生效。令牌只保存 SHA-256，不把明文写入数据库或日志。

## 兼容与边界

- 旧集成令牌没有清单标识时保留既有角色与读写范围语义，不擅自撤销现有集成权限。
- 显式空清单或损坏的名称授权不回退成全量目录；不使用名称前缀或通配符匹配。
- 精确工具授权不能代替租户、对象范围、管道限制、商业批准或 before-send 等业务检查。
- 新运行令牌未传工具名称时默认零授权；创建令牌的两个正式调用入口均传递任务清单。
- 这是本地代码与离线协议回归，不表示外部客户已接通 MCP，或已完成生产验收。

## Living System Checklist

- 归属：核心权限修补；不依赖启用行业扩展。
- 输入：现有 Agent 配置页选择的工具与 Harness 过滤结果。
- 输出：`api_tokens.scopes`、MCP 发现结果、内部工具桥。
- 反馈与日志：原 `mcp.tool_called` 审计、运行拒绝信息；拒绝保留为配置修复线索，不自动扩权。
- 可达性：沿现有 Agent 配置、工作台、API Token 列表；没有新增独立页面或配置开关。
- 连续性：不改变原失败/交接策略；权限不足时由现有执行路径反馈，用户需调整授权后再运行。
- 反停滞：沿用任务失败、取消和重试状态，不静默吞掉业务结果。
- 配置面：复用原工具选择与角色；新运行令牌自动收窄，Token 列表可见 scopes。
