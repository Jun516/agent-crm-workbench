# Jev 结构化评测：使用与证据边界

本次增量把 TypeSafe Jev 接到现有工作台的独立评测入口，评估任务相关性和输出质量。它是可选的辅助裁决；不是新 Agent Runtime，也不执行 CRM 操作、发送客户消息或更改模型权重。两个演示策略阈值和测试替身不能证明生产准确率。

## 怎样使用

1. 安装管理员在服务端配置 `TYPESAFE_API_KEY` 和 `JEV_MODEL`，再按既有部署流程重启。两项默认空，未配置会在工作台显示不可用，不影响原评测。建议使用供应商实际可用的固定版本；`jev-latest` 等别名可用但不会复用付费请求缓存。
2. 从现有导航进入 AI 工作台，选择已经结束的运行。运行中不调用 Judge。原语义评测和确定性导出入口保留。
3. 阅读外部资料共享及费用提示，勾选本次授权，再点击“运行 Jev 评测（外部服务）”。仅展开历史评测或 GET 查询不会发出模型请求。
4. 查看相关性与质量各自的选择、概率/置信度、实际模型、策略和请求指纹。低置信、`insufficient`、资料被裁剪或权限撤回时进入人工复核；先补齐证据，再由人决定是否再次明确请求。不会自动请求第二个付费 Judge。

API 使用原路径 `POST /api/v1/ai/workbench/runs/:id/evaluation?mode=jev`，沿用 manager 权限、当前组织和支持写入限制。密钥由服务端使用，不返回浏览器。

## 从输入到结果

`evaluation/route.ts` 读取组织内持久化 Run、状态、事件与子 Run；重新解析当前业务对象并拒绝已匿名化或合并的联系人。知识片段经 `loadWorkbenchObservedEvidence` 核对当前 Agent 来源授权、来源有效性及版本。适配器只接受与该 Run 原观察 ID、命名空间、修订相同的获准证据；历史工具正文不能自行成为外送权限。

`jev-judge.ts` 投影有长度上限的任务、最终答案、工具名称/状态、确定性门禁和必要知识片段。不发送隐藏推理、完整客户档案、任意原始工具正文。已知密钥、Bearer、邮箱和号码进行防御性净化；这不是通用个人信息识别器，业务方仍应在任务和答案中遵循资料最小化。

`lib/ai/jev/client.ts` 固定官方 HTTPS 地址，发送 System One Choice 协议，拒绝重定向和非法响应；限制请求/响应体积、超时和取消。不会自动重试，不记录上游原始错误正文。

裁决策略：资料完整时，置信度达到 0.8 且非 insufficient 的选择可采纳；有高置信负向选择则为 fail，全部高置信正向为 pass。其余为 needs_review。**资料受限时，正负选择都不能自动采纳，必须人工复核。** 原确定性安全失败始终保持 fail；模型裁决无法提高确定性得分。100/0 只表示二值语义策略结果，confidence 不会变成质量分或商业准确率。

固定模型只有在材料、当前授权、策略、请求/实际模型完全匹配时复用已保存回执。别名每次明确请求保留独立 attempt。Jev 历史与原 LLM Judge 分开展示；失败也保存，不因 GET 自动重试。Langfuse 仅镜像规范报告中的分数和白名单置信数值，不复制外送正文或密钥。

## 人工连续性与限制

人工从同一工作台看到 needs_review 原因、缺失材料和模型/策略回执，核对当前事实后可补材料、重新运行 Agent 或明确再次评测。当前没有新增“人工一键覆盖为通过”的接口；不会暗中修改历史结论。后续是否调整阈值需用独立标注集验证。

本轮验证为离线协议替身、API/DOM 回归、类型检查和代码检查；没有调用真实 TypeSafe、真实模型、真实客户或渠道服务。未运行新 Supabase/生产样式浏览器端到端，因此不宣称供应商联通、UI 像素布局或生产质量已验收。凭证和实际模型版本需由安装管理员配置。

官方协议：[System One](https://docs.typesafe.ai/api/system-one)、[Choice](https://docs.typesafe.ai/primitives/choice)、[Confidence](https://docs.typesafe.ai/confidence)。

## Living System Checklist

- 输入：当前组织已结束 Run 的持久化观察和重新授权证据。
- 输出：`ai_agent_eval_reports` 的独立 Jev 报告和工作台评测面板。
- 记录：已有报告表、`ai.integration_export_requested` 审计及可选脱敏 Langfuse 投影，无新数据库表。
- 入口：现有 AI 工作台 Run 评测面板，新增勾选和按钮，无新孤立页面。
- 下一步：低置信/受限/失败明确提示人工核对，未自动付费重试。
- 配置：服务端可选两变量，工作台显示是否配置和资料共享范围。
- 连续性：AI 给出结构化判断与缺口，人补充资料后明确重新运行；不自动把人类沉默当作接受。
- 反馈：原回执保留，材料/授权/规则变化使缓存失效；不自动训练或调整阈值。
- 地图：`docs/architecture/agent-services.architecture.json` 中 eval→jev→ui 与 evidence→jev。
- 归属：核心内可选辅助评测集成；零配置时原运行和原评测仍独立可用。
